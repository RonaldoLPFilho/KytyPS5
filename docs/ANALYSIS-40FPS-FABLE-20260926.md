# 40 FPS 优化路径分析（Fable）

（Fable 5.1 子代理 2026-09-26 的只读分析报告原文；综合结论见 `docs/PERF-40FPS-PLAN.md`。）

**结论摘要**
1. 判断基本成立但需修正：帧首链（均值 10.2 ms）的真正闸门不是"剔除 dispatch 排在 GPU 尾巴后面"，而是**客体回读的拷贝命令被追加到单队列末尾、排在整条 GPU 尾巴之后**——剔除批次要等客体读到回读数据后才提交（提交时刻 ≈ 尾巴结束 + 0.4 ms）；其后剔除翻译（3.3 ms 纯渲染线程 CPU、GPU 与客体都在等）和剔除结果回读串链各占约 2 ms。标签/WAIT_REG_MEM 完全不涉及 GPU（EOP 写在解析时立即 memcpy），不是杠杆。
2. 每帧周期模型（实测吻合）：尾巴结束 → +0.4 提交剔除 → +3.3 剔除翻译 → +1.9 剔除 GPU 滞后 → +0.5 主提交 → ≈15 ms CPU 受限翻译 → ≈12 ms GPU 受限重段（跨帧边界形成 4.6 ms 尾巴）= 32.5 ms。
3. 比第二队列便宜的办法存在：**"写后即快照"**（在写入者所在命令缓冲末尾立即录制热页快照，客体读只等写入者的 tick，不等整条队列），沿用单时间线；配合"同着色器连续 dispatch 快路径 + 上传搬到独立命令缓冲"压缩剔除翻译。
4. 收益取决于一个未测事实：帧首回读的数据是帧中早期产出还是尾巴末尾产出。乐观（早期）：P1+P2 可到约 25–26 ms（38–40 FPS）；悲观（尾巴产出）：约 28–30 ms（33–36 FPS），再靠异步计算队列 + GPU 时间才能逼近 40。第一步必须用追踪分支已有的 `KYTY_TRACE_WRITE_TICKS` 测这个事实（半天内可得）。
5. 推荐顺序：S0 写 tick 追踪与灵敏度实验 → S1 写后即快照 → S2 剔除翻译快路径 + 上传提升 → S3 回读/剔除专用队列（按 S0 结果二选一）→ S4 翻译窗口 CPU（mprotect/上传循环）。

## 3. 对当前判断的验证（摘要）

- 标签：`WriteAtEndOfPipe` / `WRITE_DATA` 在解析时立即 memcpy；`WaitRegMem` 只比较内存；剔除批等待的 8 个标签都在 0.5 ms 内满足。标签不构成对 GPU 完成的依赖。
- 回读：`BeginGuestReadback` 把拷贝录进当前命令缓冲、`request->tick = CurrentTick()` 后 Flush；客体 `Wait(request->tick)` 即等整条单队列执行到这里。数据多早产出无关紧要。
- 剔除依赖：客体侧（提交线程先等两条串行回读）；渲染线程侧仅标签；GPU 侧单队列顺序执行。
- 修正："渲染线程更快只会让尾巴更长"对翻译窗口成立，对帧首链不成立（剔除翻译 3.3 ms 期间 GPU 与客体都在等，敏感度≈1）。
- 其他：剔除着色器 1.65 µs/次；q49 切片约一半时间在 `DispatchDirect` 之外（PM4、服务客体回读、`CompleteDispatch`、每 dispatch 上传拷贝打断计算链）。

## 4. 优化路径（按预期收益）

- **P1 回读脱离队列积压**（帧首链 −3～−5 ms；若写入者在尾巴末尾则约 −0.5～−1）：P1a 写后即快照（移植拆分分支的反馈代码，快照时机改为热页被 GPU 写后立即）；P1b 回读专用第二队列（同族，按写入者 tick 等待）。
- **P2 剔除批翻译快路径**（帧首链 −1.5～−2 ms）：同 CS 连续 dispatch 复用程序/管线/图像绑定；上传录进独立上传命令缓冲（与主缓冲同一提交），计算链不再被上传打断；计算环切片用更小的 dispatch 批。
- **P3 异步计算队列跑计算环**（−1.5～−2 ms；风险高，需双时间线）。
- **P4 翻译窗口 CPU**：`VK_EXT_external_memory_host` 导入每帧 CPU 写、GPU 读的环形区，免上传免保护（mprotect 2 ms/帧）。
- **P5 GPU 重段**：链断点屏障、`0x208ac7300` 批、wave64。
- **P6 小项**：无 equeue 等待者时 RELEASE_MEM 不 Flush（183 → 约 90 提交/帧）。

## 5. 推荐组合

S0 写 tick 追踪（0.5 天）→ S1 写后即快照（验收：帧首链回读等待 22.8 → <8 ms/帧，剔除批提交 ≤ +2 ms，A/B ≥ +2 FPS）→ S2 P2+P6（+1～1.5 FPS）→ S3 按 S0 二选一（P1b 或 P3）→ S4 P4。
预算：乐观约 24.5 ms（40.8 FPS）；悲观约 26.5 ms，须加 P5。
