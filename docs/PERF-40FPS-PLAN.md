# 40 FPS 综合优化路径（Codex + Fable + 实测，2026-09-26）

原始报告：`docs/ANALYSIS-40FPS-CODEX-20260926.md`（gpt-6-astra，max）、`docs/ANALYSIS-40FPS-FABLE-20260926.md`（Fable 5.1）。
本文件是两者与本机实测的综合；实测数据在 `_Build/perf40b/data/`（`trace-base.bin` 帧结构、`trace-ticks.bin` 回读写入者 tick）。

## 结论

1. **最大且已被实测证实的杠杆：已完成数据的回读排在当前 GPU 尾巴后面。** 帧首卡住剔除提交的那几条回读
   （`0x3cXX83d70`、`0x3cXX8add0`，三缓冲环、每帧换地址）读的是**三帧前**写好的数据（写入者约早 500 个 tick），
   但回读拷贝被追加到单一 Vulkan 队列的末尾，要等上一帧整条 GPU 尾巴（均值 4.6 ms）跑完。这是模拟器的实现问题，不是游戏依赖，可以通用地修。
2. 帧模型（Fable 按 91 帧统计）：帧首链 10.2 ms（尾巴 4.6 → +5.0 提交剔除 → 剔除翻译 3.3 ms → 剔除 GPU 滞后 1.9 → 主提交）
   + 翻译窗口 22.5 ms（约 15 ms 受渲染线程 CPU 限制、GPU 60～75% 空闲，最后约 6 ms 受 GPU 限制）。
3. 今天渲染线程 CPU 省了 0.8 ms 却不涨帧：省在翻译窗口里（后段受 GPU 限制），没省在帧首链和窗口前段。
4. 可行路径：先做"已完成数据的回读不进主队列尾部"（预计 −3 ms），再压帧首链剩余部分和窗口前段的 CPU，最后才考虑着色器与异步计算。
   逐阶段预算约 27.5 → 26.5 → 25 ms（36 → 38 → 40 FPS），**不保证**，每阶段实测后再定下一步。

## 各方案评估

| 方案 | 来源 | 核实结果 | 结论 |
|---|---|---|---|
| 回读等写入者而非队尾（快照复用 / 专用队列） | Codex 路径3、Fable P1 | 写入者 tick 追踪：帧首闸门回读读三帧前的数据，拷贝等在尾巴后。拆分分支的"帧首预取快照"实测把异步回读 60 → 21 次/帧，但 FPS 不涨：快照本身也排在尾巴后。ReBAR 未开（CPU 可见显存只有 246 MiB），不能直接读显存。图形队列族有 16 个队列 | **第一步做**：不能用帧首快照，必须走不进主队列尾部的路：同族第二队列（只等写入者 tick）或写后立即快照 |
| 剔除翻译快路径、上传移出计算链、计算环更小批次 | Fable P2、Codex 路径5 | q49 切片 3.3 ms 渲染 CPU 在帧首链上；每 128 dispatch 的全屏障此前的上限实验没覆盖 | 第一步后重测：剔除提交提前后，剔除翻译会与尾巴重叠，收益可能变小 |
| 翻译窗口前段 CPU（原生 XPR 记录识别、剔除 dispatch、普通 draw、mprotect） | Fable P4、实测 | 窗口前段 GPU 60～75% 空闲，CPU 省下的直接变成帧时间；原生 XPR 识别（FNV 散列/键比较/索引）约占其自身时间 45% | 第三步，−1～2 ms |
| 着色器代码（wave64 双 lane、LOD 统计查询） | Codex 路径1 | LOD 查询放在分支外是导数规则要求的，只能做"统计全关"变体；收益取决于 `MipStatsCntEn` 开启比例和重段着色器 GPU 时间，都未测 | 先测再定 |
| 参数表跨对象批处理 | Codex 路径2 | 需要 bindless 级改造；过去的绑定复用都没收益 | 暂缓 |
| 异步计算队列跑计算环 | Codex 路径4、Fable P3 | 标签在解析时立即写（已核实），没有 GPU 侧依赖信息，风险高 | 前三步后仍不够才做 |

## 路径（分阶段，每步都有验收）

1. **已完成数据的回读快路径**（约 3～4 天，开关 `KYTY_READBACK_QUEUE`，默认关）
   - 每页记录最后一次 GPU 写的 tick（在跟踪器标记 GPU 脏的地方，所有写路径都经过）。
   - 异步回读：所请求页的写入者 tick 都已完成 → 拷贝提交到同族第二个队列（独立命令池与时间线；提交时等待主时间线 ≥ 写入者 tick 以建立可见性），
     客体等第二条时间线；否则走原路径。
   - 验收：校验模式下与原路径逐字节一致；ctest；截图；10 分钟游玩。追踪中帧首链均值 10.2 → ≤ 7 ms、剔除提交 ≤ +1.5 ms；同进程 A/B ≥ +2 FPS。
2. **帧首链剩余部分**（约 2～3 天）：重测后做剔除翻译快路径、上传移出计算链、批边界屏障收窄。验收：q49 切片 ≤ 2 ms，+1 FPS。
3. **翻译窗口前段 CPU 与 GPU 重段**（约 1 周）：原生 XPR 记录识别、draw 路径；测 LOD 统计开启比例与重段着色器 GPU 时间后决定是否做变体。验收：同进程 A/B 平均 ≥ 40 FPS。
4. **按需**：异步计算队列；或用户在 BIOS 开启 Resizable BAR 后，改为直接从显存读回（最简单的回读路径）。
