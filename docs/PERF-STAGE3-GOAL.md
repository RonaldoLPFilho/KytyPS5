来源：`docs/PERF-40FPS-PLAN.md` 第 3 步。用户 2026-09-26 要求直接做这一步，先把编译与测试的迭代压到极限，
设定目标、完成前不停。本文件是本阶段唯一的目标与进度来源。

## 背景（实测）

主帧翻译窗口里，前约 15 ms 受渲染线程 CPU 限制（GPU 60～75% 空闲），这段省下的 CPU 直接缩短帧；
后约 6 ms 受 GPU 限制。前段主要是图形队列 q0：XPR 剔除 dispatch（约 3,000 次/帧，约 4.5 ms）、
原生 XPR draw（约 3,500 次，5.6 ms）、普通 draw（约 1,000 次，4.3 ms）、其他 dispatch 与 PM4。

## 完成判据

1. **性能**：官方场景，PGO+LTO 构建，同进程交替测量（≥ 4 轮 × 10 秒）。对照 = 当前最佳组合
   （33 FPS 包的开关 + `KYTY_READBACK_SLOTS`、`KYTY_ASYNC_UPLOAD`、`KYTY_BDA_DIRTY_REGIONS`、
   `KYTY_GLOBAL_BARRIER_DEDUPE`）；新开关组合平均 **≥ 35.0 FPS**，且比对照高 **≥ 2.3 FPS**。
2. **画面正确**：官方机位截图与对照一致（仅动画差异）；原生 XPR 校验模式 0 不一致；ctest 无新失败（既有 3 项同一步失败）。
3. **稳定**：10 分钟脚本游玩无崩溃、无新错误；存档原样还原。
4. **工程**：每个优化一个默认关闭的开关、单独本地提交（分支 `experiment/perf-40fps-20260926`）；不推送。

## 迭代流程（先优化这个）

每轮只改一处，先量上限再实现；迭代中用 -O2 开发构建做同进程 A/B（开关运行时切换），
里程碑与验收用 PGO+LTO。构建前停掉游戏（避免与游戏同时满载，封装温度曾到 97 °C）。

## 迭代流程（已建立）

- 构建：`_Build/hist/build-pgo`（PGO+LTO）加 ThinLTO 缓存（`_Build/hist/thinlto-cache`），改一个文件增量 5～13 秒。
  迭代与验收都用同一个 PGO 构建，不再用 -O2。
- 启动：`tools/local/iter.py up [--env K=V]` = 停自己的会话（存档核对）→ 构建 → `iter-stage.py`（固定目录
  `_Build/iter/`，把上一轮驱动管线缓存改名并重签到新二进制哈希，免 200 MB 拷贝和 5 秒重编）→ `live-bench start --settle 3`。
  着色器预热改为 16 线程（`KYTY_SHADER_WARMUP_THREADS`，14.3 → 3.2 秒）。一次启动 118 → 94 秒，其中 60 秒是游戏自身（片头 18 秒 + 读盘 42 秒）。
- 测量：`iter.py ab NAME=V[+NAME=V]...`，同进程运行时切换，3 轮 × 5 秒；空跑噪声 ±0.1 FPS。一次启动测多个开关。
- 定位：`census`（按队列拆分的渲染线程时间）、`granules`、`perf record -t <Kyty.Gpu> --call-graph fp`。

## 关键实测

- 因果探针（`kyty_local_debug_delay_ns/site`，每次调用自旋）：图形队列 q0 的 dispatch / 原生 XPR / 普通 draw
  各加约 1.2 ms/帧 → 帧时间 +1.15 / +1.23 / +1.06 ms（斜率 0.9～1.0）；异步计算队列 dispatch 加 1.16 ms → +0.06 ms（斜率≈0）。
  **q0 上的渲染线程时间几乎 1:1 决定帧长；异步队列上的不影响。** 这解释了此前"省 0.8 ms 不涨帧"：省在了异步队列。
- 渲染线程每帧约 23.5 ms，其中 q0 约 22 ms（含统计开销）：剔除 dispatch 约 3,000 次、原生 XPR 约 3,500 次、
  普通 draw 约 1,000 次；同步下载 4.5 次/帧共 0.7 ms（等 GPU）；q0 内 mprotect 约 470 次/帧。
- 反证：关掉 `KYTY_ASYNC_UPLOAD`，渲染 +0.96 ms、FPS −0.60（斜率约 0.6），说明省 q0 时间能换成 FPS。

## 结论（阶段 3）

- 达成：迭代流程（构建 5～13 秒、启动 94 秒、同进程 A/B 3×5 秒）；七个默认关闭的开关，同进程验收式测量
  +1.36～+1.50 FPS（32.3 → 33.6～33.7），渲染线程 −2.0 ms/帧。
- 未达成：≥ 35.0 FPS 与 +2.3 FPS。原因见上：渲染线程时间减少现在只按约 0.6 转成帧时间，帧首链与 GPU 尾巴成了主要限制；
  阶段 3 剩余项都很小。下一步应当先用追踪分支（写入者 tick、帧首链时间线）确认帧首链到底卡在哪条依赖上，
  再决定阶段 1 的做法（第二队列 / 快照但批量屏障），而不是继续压渲染线程。
